# Учёт семейных расходов

Член семьи пишет боту в Telegram «кофе 350», и трата сохраняется: ИИ-агент сам определяет сумму, категорию и дату. Глава семьи видит траты всех в веб-панели и может их править.

Бэкенд на Go, панель на React, база PostgreSQL. Всё поднимается одной командой.

Демо веб-панели: https://ppp1qqqq.github.io/family-expenses-bot/ . Это та же панель, собранная без бэкенда: примеры трат живут в браузере, бот к ней не подключён. Публикуется на GitHub Pages автоматически при изменениях в `frontend/`.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте конфиг и заполните токен бота и доступ к LLM:

   ```bash
   cp .env.example .env
   ```

3. Запустите:

   ```bash
   docker compose up -d --build
   ```

4. Напишите боту в Telegram. Веб-панель откроется на http://localhost:8080.

Член семьи появляется в панели после первого сообщения боту. Без `TELEGRAM_BOT_TOKEN` сервис тоже запустится, но только с панелью и REST API.

## Настройки

Все настройки в `.env`, описание каждой есть в [.env.example](.env.example).

| Переменная | Что задаёт |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_ALLOWED_IDS` | Telegram ID членов семьи через запятую; пусто значит «пускать всех» |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | любой OpenAI-совместимый API с поддержкой tools: OpenAI, OpenRouter, DeepSeek, Ollama, vLLM |
| `LLM_TIMEOUT`, `LLM_TEMPERATURE` | таймаут запроса к модели и температура |
| `APP_TIMEZONE` | часовой пояс для «сегодня» и «вчера», по умолчанию `Europe/Moscow` |
| `WEB_PORT` | порт панели, по умолчанию 8080 |

Модель должна уметь вызывать инструменты (function calling). С GPT-4.1-mini, Claude и DeepSeek это работает. Локальные модели меньше 14B параметров часто путаются в инструментах.

## Что умеет бот

Бот понимает обычный текст, кнопок и команд нет (кроме `/start` со справкой).

| Пишете | Что происходит |
|---|---|
| кофе 350 | трата 350 ₽, категория «еда», сегодня |
| такси 1200 вчера | трата 1200 ₽, «транспорт», вчерашняя дата |
| сколько потратил на еду в этом месяце | сумма за месяц, считает база, а не модель |
| покажи траты за неделю | список за последние 7 дней |
| последнее было не 350, а 450 | находит последнюю добавленную трату и меняет сумму |
| удали такси | находит трату; если таких несколько, спрашивает какую |

Чужие траты в боте недоступны. У инструментов агента нет параметра `user_id`: владельца подставляет сервер из Telegram-апдейта, и каждый запрос к базе ограничен этим владельцем. Если модель передаст id чужой траты, сервис ответит «не найдено». Это проверяет тест `TestModelCannotDeleteForeignExpense`.

## REST API

Панель работает через этот API. Авторизации нет по условию задания, поэтому порт панели в compose опубликован только на `127.0.0.1`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/v1/expenses?user_id=&from=&to=&category=&q=&limit=&offset=` | список с фильтрами; в ответе `items`, `total`, `sum` |
| `POST /api/v1/expenses` | создать трату |
| `GET /api/v1/expenses/{id}` | одна трата |
| `PATCH /api/v1/expenses/{id}` | изменить переданные поля |
| `DELETE /api/v1/expenses/{id}` | удалить |
| `GET /api/v1/users` | члены семьи |
| `GET /api/v1/categories` | коды и русские названия категорий |

Даты в формате `YYYY-MM-DD`, суммы в рублях числом. Пример:

```bash
curl -s -X POST localhost:8080/api/v1/expenses \
  -H 'Content-Type: application/json' \
  -d '{"user_id": 123456789, "amount": 350, "category": "food", "comment": "кофе"}'
```

Ошибки приходят в одном формате, со статусом 400 или 404:

```json
{"error": {"code": "validation", "message": "сумма должна быть больше нуля"}}
```

Категории: `food` (еда), `transport` (транспорт), `housing` (жильё), `entertainment` (развлечения), `health` (здоровье), `shopping` (покупки), `other` (другое).

## Устройство

Архитектура и обоснование решений описаны в [docs/architecture.md](docs/architecture.md). Коротко:

```
backend/
  cmd/server/          точка входа: HTTP-сервер и бот в одном процессе
  internal/domain/     сущности, категории, разбор сумм и дат
  internal/service/    правила и проверка владельца (UserExpenses для бота)
  internal/storage/    PostgreSQL на pgx с миграциями; memstore для тестов
  internal/httpapi/    REST API
  internal/agent/      цикл ИИ-агента, системный промпт, инструменты
  internal/llm/        клиент OpenAI-совместимого API
  internal/telegram/   клиент Telegram Bot API (long polling)
  internal/bot/        обработка сообщений, история диалога
frontend/              React + Vite + TypeScript, раздаётся через nginx
```

Бот получает сообщения через long polling, поэтому публичный адрес и HTTPS не нужны.

## Разработка

```bash
cd backend && go test ./...
```

Тесты используют хранилище в памяти и фейковую LLM со сценарием вызовов, поэтому не требуют ни базы, ни ключей.

Прогон фраз из задания через настоящую модель (нужен заполненный `.env`, база не нужна):

```bash
cd backend && set -a && . ../.env && set +a && go run ./cmd/eval
```

Локальный запуск без Docker (нужен PostgreSQL):

```bash
cd backend && DATABASE_URL=postgres://... HTTP_ADDR=:8081 go run ./cmd/server
```

```bash
cd frontend && npm install && npm run dev
```

## Ограничения

Валюта одна, рубли. Траты будущей датой записать нельзя. История диалога с ботом (последние 6 ходов, 30 минут) живёт в памяти и сбрасывается при перезапуске. Панель создаёт траты только для тех, кто уже писал боту.
